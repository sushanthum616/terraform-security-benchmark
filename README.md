# A Standards-Mapped Benchmark for Evaluating Checkov, Trivy, and KICS on AWS Terraform Security Misconfigurations

This repository is a local, reproducible benchmark of intentionally vulnerable and corrected AWS Terraform snippets. Its contribution is: “The project’s contribution is a reproducible, standards-mapped Terraform benchmark used to measure the detection strengths, weaknesses, and coverage gaps of multiple Infrastructure-as-Code security scanners.”

## Research question

How consistently do Checkov, Trivy, and KICS detect a defined set of AWS Terraform misconfigurations, and where do their findings overlap or diverge?

## Scope and safety

The benchmark is static Terraform source only. It uses fictional names and values, has no backend, data sources, credentials, account IDs, or real IP addresses, and must never be deployed. No AWS resources were created or queried for this project.

## Structure

Each `benchmark/case-*` directory contains `vulnerable.tf`, `secure.tf`, and `metadata.yaml`. `docs/benchmark-matrix.csv` is the machine-readable case index. Scanner evidence belongs in `results/`; normalized output is generated by `scripts/normalize_results.py`.

## Tools and reproduction

Tool availability and exact versions are recorded in `docs/tool-versions.txt`. When installed locally, run only static commands:

```text
terraform fmt -recursive benchmark
terraform validate -json benchmark/case-01-public-s3
checkov -d benchmark --framework terraform --output json --output-file-path results/checkov/vulnerable.json
trivy config --format json --output results/trivy/vulnerable.json benchmark
kics scan -p benchmark -o results/kics --report-formats json,sarif
python scripts/normalize_results.py
```

Do not run `terraform plan`, `apply`, `destroy`, `import`, or `refresh`; do not use AWS CLI or any cloud credentials. The commands above are templates and must be recorded with their actual exit status and duration before results are considered evidence.

## Evaluation metrics

Detection rate is true positives divided by the 12 benchmark issues. The comparison also reports missed cases, scanner-exclusive detections, overlaps, additional valid findings, scan time, and whether remediation guidance was available.

## Current status

All 12 case pairs and standards metadata are present. The three priority cases are authored end to end at the source/metadata level. Scanner execution and normalization are pending because Checkov, Trivy, KICS, Terraform, and Python were not available on PATH in the initial environment.

## Known limitations

These are minimal static examples, not deployable applications. Scanner versions, rule packs, parser behavior, and provider schemas can change results. A CIS mapping is recorded only where a direct correspondence is defensible; otherwise it is `not_applicable`. No scanner finding is fabricated while scanners are unavailable.
